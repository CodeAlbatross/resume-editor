# 项目区块富文本与亮点分级设计文档

> **日期**: 2026-08-07
> **状态**: 已获用户批准（分节评审通过）

## 1. 目标

解决项目区块的排版问题：项目亮点中的标题行（如 `【板块一】xxx`）被渲染成普通圆点、层级不清。升级项目编辑器，让描述区支持轻量 Markdown、亮点区支持分级结构，同时保持数据零迁移。

## 2. 功能范围

| # | 能力 | 说明 |
|---|---|---|
| 1 | 亮点分级渲染 | 渲染时按规则识别主标题/子条目/普通亮点，分别用不同样式 |
| 2 | 结构化亮点编辑器 | 每条亮点一个输入框，支持层级切换（标题/子项/普通）+ 排序 + 删除 |
| 3 | 描述轻量 Markdown | 项目描述支持 `**加粗**` `*斜体*` `` `代码` `` `- 列表` |
| 4 | 三模板同步 | React 预览 + EJS 导出的 classic/modern/compact 三套模板规则一致 |

**范围限定**：只做**项目区块**（ProjectEditor + projects 渲染）。工作经历、摘要等其他区块不改。

## 3. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 实现方式 | 方案 A：渲染层解析分级 | 数据零迁移，现有简历直接生效 |
| Markdown | 轻量子集（4 种语法），自研极简解析器 | 无新依赖，与项目「零依赖」风格一致 |
| 亮点分级 | 按钮式编辑器 + 渲染识别规则 | 用户不需要懂 Markdown 语法 |
| 数据 | 保持 `Project` 结构不变 | 零迁移，兼容现状 |
| 富文本库 | 不引入（TipTap/Editor.js 等） | YAGNI，复杂度过高 |

## 4. 分级规则（唯一权威定义）

`highlights` 数组每项文本，按前缀识别为三级结构。**React 预览与 EJS 导出必须使用完全一致的规则**：

| 级别 | 识别规则 | 渲染样式 |
|---|---|---|
| 主标题 | 以 `【` 开头且含 `】`（如 `【板块一】xxx`） | 无圆点、加粗、小标题样式、占整行不缩进 |
| 子条目 | 以空格/制表符开头（前导缩进 ≥1） | 次级圆点 `◦`、左侧缩进、正常字号 |
| 普通亮点 | 其他（无前缀、无缩进） | 标准圆点 `•`、正常字号 |

**示例**（compact 渲染效果）：
```
项目经历
  板块一：Harness 工程推广与反馈闭环          ← 标题样式，无圆点
    • 业务线接入推广：深入一线协助...           ← 普通亮点
    • 反向推进产品进化：将实战中的卡点...       ← 普通亮点
```

## 5. 编辑器 UI（ProjectEditor 每条 item 内）

```
项目亮点
┌─────────────────────────────────────────────┐
│ T  ▾  业务线接入推广：深入一线协助各业务方...   │
│ T  ▾  反向推进产品进化：将实战中的卡点...      │
│ [标题]【板块一】Harness 工程推广与反馈闭环     │
│ T  ▾  系统架构：整合 语雀×3 + 源码×4...       │
│        ▲ ▲ ▼ ▼            [删除]  [+ 添加]   │
└─────────────────────────────────────────────┘
```

**每条亮点**：一行输入框 + 层级切换按钮 + 上移/下移 + 删除

### 层级切换规则

| 操作 | 行为 |
|---|---|
| 切到「标题」 | 若文本无 `【】` → 包成 `【文本】`；已有 → 保持 |
| 切到「子条目」 | 若无缩进 → 前置 2 空格 |
| 切到「普通」 | 去掉 `【】` 包裹 + 去掉前导缩进 |
| 删除 | 移除该条 |
| 上移/下移 | 数组内交换，保留各自层级 |

**体验细节**：输入框占位符随层级变化（标题→"如【板块一】xxx"，子条目→"缩进子项..."，普通→"亮点描述..."）。编辑即 `updateSection` 实时保存。

## 6. 描述区轻量 Markdown

| 语法 | 渲染 |
|---|---|
| `**加粗**` | `<strong>` |
| `*斜体*` | `<em>` |
| `` `代码` `` | `<code>`（等宽） |
| `- 条目` | `<ul><li>` |
| 普通文本 | 段落 |

**注意**：`- ` 开头的行转列表；Markdown 解析只做上述 4 种子集，不支持标题/链接/表格/图片。

## 8. 兼容性

| 项 | 处理 |
|---|---|
| 现有纯 string[] 无 `【】`/缩进 | 全部按普通亮点渲染，行为不变 |
| 现有 `【板块一】` 数据 | 自动识别为主标题，零迁移 |
| 工作经历 highlights | 本次不动 |
| 已有纯文本描述（无 Markdown 语法） | 渲染结果不变 |

## 9. 测试

- 前端单元：`markdown.ts` / `highlightLevel.ts` 的解析规则测试（`**加粗**`、`【】`识别、缩进识别、边界）
- EJS 一致性：三模板解析规则与前端一致
- 手动验收：
  1. 现有简历（含 `【板块一】`）预览正确分级
  2. 编辑器设标题/子项/普通 → 预览/导出正确
  3. 描述写 `**加粗**` `- 列表` → 正确渲染
  4. 导出 PDF 与预览一致

## 10. 明确不做（YAGNI）

- 工作经历/摘要等其他区块的富文本
- 复杂 Markdown（表格、链接、标题、图片）
- 真正的富文本库（TipTap 等）
- 数据结构迁移
